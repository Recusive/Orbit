### 8.1 Frontend Patterns

**Try/Catch with Typed Errors:**

```typescript
try {
  const result = await readFile(path);
} catch (err: unknown) {
  const message = err instanceof Error ? err.message : 'Unknown error';
  console.error('[Module] Failed:', message);
}
```

**Fire-and-Forget:**

```typescript
clearCrashLog().catch((err: unknown) => {
  console.error('[Module] Failed to clear:', err);
});
```

**Error Boundary:**

```typescript
class ErrorBoundary extends Component<Props, State> {
  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, errorInfo: ErrorInfo): void {
    console.error('ErrorBoundary caught:', error, errorInfo);
    this.props.onError?.(error, errorInfo);
  }
}
```

```json
{"type":"agent_message","sessionId":"abc","message":{...}}
```

## 10. Logging Patterns

### 10.1 Frontend Logging

**Pattern:** Prefixed console with context

```typescript
console.warn('[Snowflake] Sending:', message.type);
console.error('[useCrashCheck] Failed:', err);
```

**ESLint Rule:** `no-console: ['error', { allow: ['warn', 'error'] }]`

### 10.2 Backend Logging

**Framework:** tracing + tauri-plugin-log

**Configuration:**

```rust
enum LogMode {
    Prod,   // warn/error only
    Dev,    // info (deps), debug (snowflake)
    Debug,  // debug (deps), trace (snowflake)
}
```

**Usage:**

```rust
use tracing::{debug, error, info, warn};

debug!(terminal_id = %id, shell = %shell, "Terminal created");
warn!(terminal_id = %id, error = %e, "PTY read error");
error!("Failed to open PTY: {e}");
```

### 10.3 Agent-Bridge Logging

**Output:** stderr only (stdout reserved for IPC)

```typescript
// logger.ts
function log(level: string, context: object, message: string): void {
  const timestamp = new Date().toISOString();
  process.stderr.write(
    `[${timestamp}] [${module}] [${level}] ${JSON.stringify(context)} ${message}\n`
  );
}
```

## 11. Potential Issues

### 11.1 Type Safety Gaps

| Issue                                       | Location      | Impact                  |
| ------------------------------------------- | ------------- | ----------------------- |
| No shared types between Rust and TypeScript | Core types    | Manual sync required    |
| SDK boundary uses loose validation          | agent-bridge  | May accept invalid data |
| Some stores use `unknown` for tool inputs   | tool-store.ts | Type narrowing needed   |

### 11.2 Performance Considerations

| Concern                         | Location          | Recommendation                |
| ------------------------------- | ----------------- | ----------------------------- |
| Terminal output not throttled   | terminal-store.ts | Consider debouncing           |
| Large file tree in memory       | file-store.ts     | Virtual scrolling for display |
| Message validation on every IPC | use-tauri.ts      | Cache validated types         |

### 11.3 Error Handling Gaps

| Gap                                    | Location       | Recommendation               |
| -------------------------------------- | -------------- | ---------------------------- |
| Silent failures in fire-and-forget     | Multiple hooks | Add optional error callbacks |
| No structured error reporting          | Frontend       | Add error telemetry          |
| Panic hook doesn't capture all context | crash.rs       | Capture more thread state    |

### 11.4 Logging Improvements Needed

| Gap                        | Recommendation                        |
| -------------------------- | ------------------------------------- |
| No request tracing         | Add correlation IDs to IPC messages   |
| No performance metrics     | Add timing to critical paths          |
| No log aggregation         | Consider log shipping to file/service |
| Console logs in production | Add proper logging framework          |
