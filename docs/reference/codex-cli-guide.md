## Execution Modes

### Interactive (Default)

```bash
codex "Your prompt here"
```

Features:

- Full TUI interface
- Real-time streaming responses
- Command approval prompts
- Session history

### Non-Interactive (`exec`)

```bash
codex exec "Your prompt here"
```

Features:

- One-shot execution
- Scriptable output
- JSON output support (`--json`)
- Output file support (`-o FILE`)

### Full Auto Mode

Skip approval prompts with sandboxed execution:

```bash
codex --full-auto "Refactor this function"
```

Equivalent to: `-a on-request --sandbox workspace-write`

## Sandbox Policies

Codex uses sandboxing to protect your system. Choose a policy based on your needs:

| Policy              | Flag                    | Permissions                         |
| ------------------- | ----------------------- | ----------------------------------- |
| **Read Only**       | `-s read-only`          | Can only read files                 |
| **Workspace Write** | `-s workspace-write`    | Write to workdir, `/tmp`, `$TMPDIR` |
| **Full Access**     | `-s danger-full-access` | Full system access (dangerous!)     |

### Example: Workspace Write

```bash
codex -s workspace-write "Create a new component"
```

### Sandbox Permissions in Config

```toml
# ~/.codex/config.toml
sandbox_permissions = ["disk-full-read-access"]
```

## Approval Policies

Control when Codex asks for permission before executing commands:

| Policy       | Flag            | Behavior                                      |
| ------------ | --------------- | --------------------------------------------- |
| `untrusted`  | `-a untrusted`  | Only trusted commands (ls, cat, sed) auto-run |
| `on-failure` | `-a on-failure` | Ask only if command fails                     |
| `on-request` | `-a on-request` | Model decides when to ask                     |
| `never`      | `-a never`      | Never ask, failures go to model               |

### Example: Never Ask

```bash
codex -a never exec "Run all tests"
```

## Configuration

Codex uses `~/.codex/config.toml` for configuration.

### Example Configuration

```toml
# Model settings
model = "gpt-5.2-codex"
model_reasoning_effort = "xhigh"

# Feature flags
[features]
web_search_request = true

# Project trust levels
[projects."/path/to/trusted/project"]
trust_level = "trusted"

[projects."/path/to/untrusted/project"]
trust_level = "untrusted"
```

### Config Overrides via CLI

```bash
# Override model
codex -c model="o3" "Your prompt"

# Override sandbox permissions
codex -c 'sandbox_permissions=["disk-full-read-access"]' "Your prompt"

# Use a profile
codex -p my-profile "Your prompt"
```

### Reasoning Effort Levels

| Level    | Description                   |
| -------- | ----------------------------- |
| `low`    | Fast, less thorough reasoning |
| `medium` | Balanced reasoning            |
| `high`   | More thorough reasoning       |
| `xhigh`  | Maximum reasoning depth       |

## Troubleshooting

### Sandbox Restrictions

If Codex can't write to a location:

```bash
# Add the directory as writable
codex --add-dir ~/Desktop "Create file on Desktop"

# Or use full access (dangerous)
codex -s danger-full-access "Create file anywhere"
```

### Authentication Issues

```bash
# Re-login
codex logout
codex login
```

### Skip Git Repo Check

```bash
codex exec --skip-git-repo-check "Run outside a git repo"
```
