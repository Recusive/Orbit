## Summary

Explored the frontend layer end-to-end across chat components, animation utilities, layout hooks, terminal addons, and the theme system. The Rust backend was reviewed but its error handling patterns are intentional (the LSP crate uses `#[expect(clippy::map_err_ignore)]` with documented reasons, and browser commands use consistent `ok_or` strings).

The most impactful area was **silent IPC error handling** — four fixes (7, 8, 12, plus the existing git polling catch) added `.catch()` handlers to ~15 `void invoke(...)` calls across the theme provider, git polling, and traffic light hooks. These were invisible failure paths where Tauri backend errors were silently swallowed with no diagnostic trace. The second strongest area was **accessibility** — five fixes brought keyboard activation to status bar buttons, `type="button"` consistency to all 14 tool widgets plus message actions, `aria-label` to the diff stats button, and `prefers-reduced-motion` to the two remaining animation components that lacked it. Code quality fixes removed two prohibited cast patterns (`as string`, `as unknown as`) and replaced a bare `console.error` with the structured logger.

One pre-existing test failure exists: `app-activity-panel-layout.test.tsx` expects `reviewPanelWidth` of 416 but gets 560 — unrelated to nightshift changes (reproduces on the base commit).

## Fixes

### 1. Add type="button" to ActionButton in message-actions (cycle 1)

- **Category**: A11y
- **Files**: `apps/agent/src/components/chat/messages/message-actions.tsx`
- **Commit**: `dc907dfc`
- **What I found**: The `ActionButton` component rendered `<button>` elements without an explicit `type` attribute. Buttons default to `type="submit"`, which can cause unintended form submission if the message actions are ever nested inside a `<form>` context.
- **Why it matters**: Latent form submission bug if component is ever composed inside a form.
- **What I did**: Added `type="button"` to the underlying `<button>` element in ActionButton.

### 2. Add aria-label and type="button" to DiffStatsButton (cycle 1)

- **Category**: A11y
- **Files**: `apps/agent/src/components/layout/content-top-bar.tsx`
- **Commit**: `4ce2559f`
- **What I found**: The `DiffStatsButton` in ContentTopBar had no `aria-label`, making it invisible to screen readers. It also lacked `type="button"`.
- **Why it matters**: Screen reader users cannot identify or activate the diff stats action.
- **What I did**: Added `aria-label` sourced from the existing tooltip text and added `type="button"`.

### 3. Remove unsafe `as string` cast in loadImage (cycle 1)

- **Category**: Code Quality
- **Files**: `apps/agent/src/lib/utils/image-utils.ts`
- **Commit**: `307b1108`
- **What I found**: `FileReader.result` has type `string | ArrayBuffer | null` but was cast with `as string` — prohibited by CLAUDE.md. If the FileReader ever returned a non-string result, this would silently produce broken behavior.
- **Why it matters**: Prohibited type-safety bypass that could produce silent runtime corruption.
- **What I did**: Replaced the unsafe cast with a `typeof` guard that rejects the promise with a clear error message when the result is not a string.

### 4. Add type="button" to all tool widget expand/collapse buttons (cycle 1)

- **Category**: A11y
- **Files**: 14 files in `apps/agent/src/components/chat/tools/`
- **Commit**: `c69d5052`
- **What I found**: Every tool widget's expand/collapse `<button>` lacked `type="button"`. Only `generic-tool-widget.tsx` already had it.
- **Why it matters**: Implicit `type="submit"` is a latent bug if these widgets are ever rendered inside a form context.
- **What I did**: Added `type="button"` to all 14 tool widget expand/collapse buttons.

### 5. Remove unsafe `as unknown as React.MouseEvent` casts in tool widgets (cycle 2)

- **Category**: Code Quality
- **Files**: `apps/agent/src/components/chat/tools/write-tool-widget.tsx`, `apps/agent/src/components/chat/tools/edit-tool-widget.tsx`
- **Commit**: `002823c4`
- **What I found**: Both `handleFileClick` functions were typed as `(e: React.MouseEvent)` but called from `onKeyDown` handlers with `e as unknown as React.MouseEvent` — a prohibited double-cast per CLAUDE.md. The function only uses `preventDefault()` and `stopPropagation()`, which exist on all `React.SyntheticEvent`.
- **Why it matters**: `as unknown as` bypasses type safety entirely. If the handler ever accessed mouse-specific properties, the cast would silently produce `undefined` at runtime.
- **What I did**: Widened `handleFileClick` parameter type from `React.MouseEvent` to `React.SyntheticEvent` and removed the casts.

### 6. Add `prefers-reduced-motion` support to BlurReveal and ShimmerText (cycle 2)

- **Category**: A11y
- **Files**: `apps/agent/src/components/welcome/blur-reveal.tsx`, `apps/agent/src/components/ui/shimmer-text.tsx`
- **Commit**: `f0a14318`
- **What I found**: Both components use `motion/react` animations but don't call `useReducedMotion()`. BlurReveal animates each character individually with blur+opacity+transform. ShimmerText runs an infinite shimmer loop. This violates the project's high-priority rule "Always respect prefers-reduced-motion media query."
- **Why it matters**: Users with vestibular disorders or motion sensitivity get animated text they can't disable. All 15 tool widgets already respect this; these 2 were the only gaps.
- **What I did**: Added `useReducedMotion()` to both. BlurReveal renders static text immediately and fires `onComplete` on trigger. ShimmerText renders plain text without the gradient shimmer.

### 7. Add missing error handler on getSettings() in useGitPolling (cycle 2)

- **Category**: Error Handling
- **Files**: `apps/agent/src/hooks/git/use-git-polling.ts`
- **Commit**: `eed245a4`
- **What I found**: `getSettings()` (a Tauri IPC call) was called with `.then()` but no `.catch()`. If the backend fails, the promise rejection is silently swallowed — `gitSettings` stays `null` and auto-fetch silently falls back to defaults with no diagnostic trace.
- **Why it matters**: Silent IPC failures are invisible during debugging. No log entry to trace "auto-fetch isn't using my settings."
- **What I did**: Added `.catch()` with `logger.warn()`. The fallback-to-defaults behavior was already correct; the missing piece was the diagnostic logging.

### 8. Add error handling to native theme IPC calls in ThemeProvider (cycle 2)

- **Category**: Error Handling
- **Files**: `apps/agent/src/providers/theme-provider.tsx`
- **Commit**: `6bf4250a`
- **What I found**: The `useEffect` that syncs liquid glass and native defocus color had 12 `void invoke(...)` calls with no `.catch()`. Five distinct native APIs could fail silently.
- **Why it matters**: Theme switching failures cause visual inconsistency (wrong glass tint, opaque frost in light mode) with no way to diagnose the root cause.
- **What I did**: Extracted a shared `catchNative` handler that logs via `logger.warn()`. Replaced all `void invoke(...)` and `void setLiquidGlassEffect(...)` with `.catch(catchNative)`.

### 9. Add keyboard activation to StatusItem role="button" elements (cycle 2)

- **Category**: A11y
- **Files**: `apps/agent/src/components/layout/status-bar.tsx`
- **Commit**: `22328271`
- **What I found**: The `StatusItem` component correctly sets `role="button"` and `tabIndex={0}` on interactive items, making them focusable. But there was no `onKeyDown` handler — keyboard users could Tab to these elements but couldn't activate them with Enter or Space.
- **Why it matters**: WCAG 2.1 SC 2.1.1 (Keyboard) requires all interactive elements to be operable via keyboard.
- **What I did**: Added a `handleKeyDown` callback (memoized with `useCallback`) that calls `onClick()` on Enter or Space, with `preventDefault()` to suppress Space scroll.

### 10. Replace console.error with structured logger in useSearch (cycle 2)

- **Category**: Code Quality
- **Files**: `apps/agent/src/hooks/ui/use-search.ts`
- **Commit**: `96209268`
- **What I found**: The `performSearch` promise chain used `.catch(console.error)` — violating the project's "No console.log — Use structured logger" rule.
- **Why it matters**: `console.error` output is unstructured, has no `[useSearch]` prefix, and won't appear in structured log filtering.
- **What I did**: Added `createLogger('useSearch')` and replaced `.catch(console.error)` with `.catch((err) => logger.error('Unexpected search failure', { err }))`.

### 11. Guard against NaN exit code in shell integration addon (cycle 3)

- **Category**: Code Quality
- **Files**: `apps/agent/src/lib/terminal/addons/shell-integration-addon.ts`
- **Commit**: `9b18f7ff`
- **What I found**: `parseInt(parts[1], 10)` parses the shell's exit code from an OSC 633;D sequence. If the shell sends non-numeric data, `parseInt` returns `NaN`, which passes the `exitCode !== undefined` guard and propagates to the terminal store. Downstream `exitCode === 0` comparisons silently fail.
- **Why it matters**: A NaN exit code shows as neither success nor failure — a confusing ghost state in the terminal UI.
- **What I did**: Added a `Number.isNaN()` guard that coerces NaN back to `undefined`, matching "no exit code provided" semantics.

### 12. Add catch handler to traffic light IPC call (cycle 4)

- **Category**: Error Handling
- **Files**: `apps/agent/src/hooks/ui/use-traffic-lights.ts`
- **Commit**: `ef18a16b`
- **What I found**: `void invoke('set_traffic_lights_visible', ...)` in `useTrafficLights` swallowed promise rejections silently. If native traffic light positioning fails, there's no diagnostic trace.
- **Why it matters**: Traffic light positioning failures would be invisible — the sidebar toggle would appear to work but native window controls wouldn't move.
- **What I did**: Added `createLogger('useTrafficLights')` and replaced `void invoke(...)` with `invoke(...).catch(...)` using `logger.warn()`, consistent with fixes 7 and 8.

## Recommendations

1. **Add `jsx-a11y/button-has-type` ESLint rule.** This shift found missing `type="button"` across 16 buttons in 15 files. An ESLint rule would catch this at lint time and prevent regression.

2. **Audit remaining `void invoke(...)` calls.** Fixes 7, 8, and 12 addressed silent IPC failures in three hooks, but there are likely more `void invoke(...)` patterns elsewhere. A codebase-wide grep for `void invoke` would surface them — each is an invisible failure path.

3. **Add per-panel error boundaries.** Error boundaries exist at the mode level and on individual message items, but panels, tabs, and sidebar sections are largely unprotected. See logged issue #1.

4. **Extract shared `ToolWidgetHeader` component.** All 15 tool widgets duplicate the same expand/collapse button pattern. A shared component would eliminate duplication and ensure new widgets get correct accessibility attributes automatically.

5. **Fix pre-existing test failure.** `app-activity-panel-layout.test.tsx` expects `reviewPanelWidth` of 416 but gets 560. Reproduces on base commit — the test needs updating after a recent layout change.

6. **Next nightshift: focus on Rust test coverage.** This shift was frontend-only. The Rust backend's error handling is intentional, but the crates have business logic with thin test suites. Future shifts should add tests for `crates/common/fs`, `crates/common/git`, and `crates/common/conversations`.
